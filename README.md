# NashHash / Website

**Autonomous systems. Human terms.**

NashHash is an independent AI systems and trust engineering studio based in Japan. This repository serves its public-facing website via GitHub Pages.

## Business and research

- Independent research and engineering practice focused on autonomous agents, identity, delegation and verifiable agent interactions.
- Local-first personal agents for resource-constrained smartphones: application research and development.
- Public-key continuity, signed interactions and verifiable provenance: protocol research and prototyping.
- Machine-readable permission scopes, approval conditions and revocation: infrastructure design research.
- Custom agent systems engineering, identity/trust protocol design, evaluations, technical integration and support: commercial service areas.

Research directions are clearly differentiated from completed products. Signatures establish key control or continuity, not legal identity. Technical authorization records are not a substitute for legal contracts.

## Design and access

- English is the default language; Japanese can be selected and preference is stored locally.
- Responsive desktop and mobile navigation, semantic page structure, keyboard access, alt text, and reduced-motion support.
- Native wheel scrolling with gentle parallax, changing three-step system illustration, scroll progress, animated section reveals and an accordion for service descriptions.
- Intentionally light, editorial visual design. No continuously running WebGL background.
- Standalone static HTML, CSS and JavaScript; no JS front-end build step.

## Before publishing outreach

- Check that [nashhash.dev](https://nashhash.dev/) resolves to the GitHub Pages site via DNS and HTTPS.
- Verify contact@nashhash.dev is a real, monitored inbox. A published email address does not create a mailbox.
- Confirm company description, city, development stages, and service engagement scope remain accurate.
- Add links to genuine public technical artifacts as and when they are available, rather than inventing use cases or metrics.

## Review process

Three complete reviews were performed before merge: (1) first-time-visitor / investor narrative and claim quality, (2) design responsiveness, motion preferences and image provenance, and (3) static functional, language and accessibility checks.
HTML and JavaScript were checked statically; a real-browser live rendering / production DNS check must still be performed after deployment.
